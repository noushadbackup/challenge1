# Round 4: 9 TCN seeds and Chute04 segment features (2026-10-17)

Base: `final_norep` (the submission). Both ideas came from the round-3 error analysis:
- **9 TCN seeds** (`tcn.seeds = 9`): average 9 TCN members instead of 3, to reduce seed noise.
- **Chute04 segment features** (`clip.segclf.features = "phys+x"`, config `final_norep_x`): 6 extra features for the
  segment classifier (per-radar peak frame difference, motion burst, static change at the peak, stillness after it),
  aimed at falls from a chair, whose motion burst and static change are weaker.

Each was compared with the base on TCN seed sets that no selection had used (team GPU, `tools/confirm.py`).
Rule: P(gain) >= 0.90, >= 3/4 folds improve, val >= base - 0.02.

## Seed sets 6-8 (`make confirm DEVICE=cuda SUITE=r4`)

The Chute04 features passed only at the margin (P 0.906), and three candidates were tested. Before switching, they
were re-tuned on the round-3 base runs (seed sets 3-5, which never saw this idea) and pooled over 6 seed sets.

On seed sets 3-5 alone the gain is about zero, so the seed-6-8 pass was mostly noise.

The CPU refit of `final_norep_x` (same TCN/HGB/PCA files as `final_norep`, byte for byte) scores 0.9444 on val
(63/2/4) against 0.9373 (63/3/4): one false alarm fewer, within the val noise.

## Decision

**No change: the submission stays `final_norep`.**
- The Chute04 features are slightly positive on average (+0.002) but fail the probability and fold rules.
- 9 TCN seeds fail the probability rule and triple the TCN training time.
- `final_norep_x` stays in `uwbfall/configs/` as a documented, unused candidate. `retune` now copies any number of TCN
  seed files (a bug found here: it copied only seeds 0-4).
